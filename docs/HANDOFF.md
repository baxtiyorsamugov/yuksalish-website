# Передача проекта

## Текущее состояние

Ветка `feat/public-rebrand`. Публичный интерфейс PHP с локальными ресурсами и выбранным реальным содержимым. Старый стенд на `192.168.0.140:8089` не изменён. На этой машине отдельный просмотр: `http://127.0.0.1:8090/uz`.

Основные слои: `app/src/ContentRepository.php` получает выбранные материалы; `app/src/templates/` выводит страницы; `app/src/translations.php` хранит четыре языка интерфейса. CSS/JS и изображения находятся в `app/public/assets/`. SQL в шаблонах отсутствует. Новые публичные API не добавлялись.

Карта разделов: о движении / деятельность / проекты / медиа / регионы, отдельное участие. Перенаправления и сохранённые записи перечислены в `legacy-routes.json`. Полный старый архив не перенесён; старые невыбранные ID не подменяются другими материалами.

## Запуск на другом компьютере

1. Получить эту ветку и прочитать `README.md` и `DESIGN.md`.
2. Запустить PHP 8.4+ через `scripts/start-preview.ps1` или использовать существующий Docker Compose. `.tools/` содержит только локальные инструменты текущего компьютера и не передаётся через Git.
3. Выполнить PHP/HTTP/браузерные проверки из README. Runtime-данные, секреты и исходные архивы получать отдельным согласованным способом, не через Git.

## Точный следующий этап

После визуального просмотра главной, каталога, статьи и мобильных версий согласовать полный реестр публичных материалов для миграции. Подключить его через интерфейс ContentRepository к новой согласованной базе, дополнить отсутствующие переводы и карту старых URL. Не открывать legacy_reference на запись. Схему хранения и обработку заявок проектировать отдельно с редакторскими сценариями. Перед публикацией определить production URL и проверить SEO-метаданные, права на материалы и юридические тексты.
